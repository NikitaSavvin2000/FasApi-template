# Процесс выполнения задачи

Этот файл применяется, когда задача передана ссылкой или явно требует
следовать `AGENT_TASK.md`. Структура, границы слоёв и постоянные правила живут
только в [AGENTS.md](AGENTS.md).

## 1. Разбор

1. Прочитать задачу, `AGENTS.md`, затронутые модули и тесты.
2. Выполнить `git status --short`; не перезаписывать существующие изменения.
3. Сформулировать наблюдаемое поведение: входы, результаты, ошибки,
   ограничения, побочные эффекты и изменение OpenAPI.
4. Найти похожий код через `rg` в `src/` и `tests/`; расширять его вместо
   дублирования.
5. Для нетривиальной задачи заполнить `.agent/task-template.md` и сообщить
   короткий план пользователю.

## 2. Реализация через TDD

Для каждого изменения выполнять небольшую итерацию:

1. Написать один минимальный тест полезного поведения.
2. Запустить только этот тест.
3. Реализовать изменение в слое, указанном в `AGENTS.md`.
4. Повторно запустить тест и исправить расхождения.
5. Запустить релевантный набор: `unit`, `contracts` или оба.

Контрактные тесты обходят OpenAPI универсально; не добавлять в них список
конкретных route-путей. Тесты должны проверять внешнее поведение, а не строки
покрытия или внутренние детали.

## 3. Конфигурация и безопасность

- Новую настройку добавлять в `Settings`, пример конфигурации и документацию.
- Не менять `.env`, `config.yaml`, `credential.yaml` без явного запроса.
- Не выполнять сброс БД, миграции, удаление данных или внешние действия без
  явного разрешения пользователя.
- Не хранить OpenAPI YAML в репозитории: контракт берётся у запущенного
  приложения.

## 4. Завершение

```bash
python scripts/verify.py all
git diff --check
```

В результате сообщить: что изменено, какие проверки прошли и что не
проверялось с причиной.
