# Руководство для участников

## Назначение и архитектурные принципы

Это самостоятельный шаблон микросервиса FastAPI с устанавливаемым `src` layout.
Точка сборки — `fastapi_template.main:create_app`, а пользовательский запуск —
`python main.py` после активации окружения. Импорт модуля не запускает сервер,
не открывает соединения и не выполняет миграции.

Каждый публичный HTTP URL начинается с версии: `/v1`, `/v2` и далее. Major-номер
из `[project].version` в `pyproject.toml` задаёт префикс основной версии через
`core/version.py`; версия `1.0.0` означает `/v1`. Каждая версия монтируется как
отдельное FastAPI-приложение: её `/vN/docs`, `/vN/redoc` и `/vN/openapi.json`
содержат только маршруты этой версии.

## Структура проекта

| Путь | Содержимое и правила |
| --- | --- |
| `main.py` | Корневая Python-точка запуска `python main.py`; только передаёт управление пакету. |
| `src/fastapi_template/__main__.py` | Загрузка настроек и запуск Uvicorn. |
| `src/fastapi_template/main.py` | Фабрика приложения, маршрутизация, middleware и живая OpenAPI-схема. |
| `api/` | HTTP-слой: роутеры, зависимости и форматирование SSE; обработчик остаётся коротким. |
| `api/vN/routes/` | Обработчики конкретной версии API; подключение — через `api/vN/router.py`. |
| `schemas/` | Публичные Pydantic-схемы запросов, ответов и SSE с описаниями, примерами и ограничениями. |
| `models/` | Доменные значения без HTTP и модели хранения. |
| `services/` | Прикладная логика без зависимостей от FastAPI Request/Response. |
| `clients/` | Конкретные клиенты внешних сервисов при реальной интеграции. |
| `db/` | Выбор источника БД, подключения, репозитории и модели хранения. |
| `local_services/` | Локальная SQLite БД, её SQL-шаблоны и явная утилита управления; бинарный файл БД не коммитится. |
| `configs/config.py` | Единственное место определений, загрузки и валидации настроек. |
| `core/` | Lifecycle, middleware, логирование, ошибки и версия проекта. |
| `utils/` | Только маленькие независимые помощники, не прикладная логика. |
| `tests/unit/` | Изолированные тесты логики, конфигурации и инфраструктуры. |
| `tests/contracts/` | Универсальные проверки OpenAPI живого сервиса и ограничений его схем. |
| `tests/integration/` | Тесты настоящего процесса, сети и интеграции компонентов при необходимости. |

Не смешивайте API-схемы и модели хранения, не передавайте HTTP-объекты в сервисы
без необходимости и не меняйте `sys.path`. Используйте абсолютные импорты от
`fastapi_template`, предотвращайте циклические импорты и переиспользуйте уже
существующие сервисы и helpers перед созданием новых.

## Окружение и запуск

Используйте Python 3.11 и uv. Сначала синхронизируйте зависимости, затем
активируйте окружение и запускайте Python-инструменты через `python -m`:

```bash
uv sync --locked --group dev
source .venv/bin/activate

python main.py
python -m pytest -v
python -m mypy src
python -m pre_commit run --all-files
```

Runtime-настройки находятся только в `configs/config.py`. Их приоритет:
программные overrides, окружение процесса, `.env`, YAML и defaults. Для
вложенности используйте `APP_` и `__`, например `APP_SERVER__WORKERS=4`.
Обычные значения живут в `config.yaml`, секреты — в `credential.yaml`; рабочие
конфигурации не коммитятся. `workers` — процессы Uvicorn, а
`thread_pool_tokens` — лимит AnyIO на процесс. Reload работает только с одним
worker.

`APP_LOCAL_DEVELOPMENT=true` выбирает SQLite в `local_services/local.sqlite3`
и применяет `local_services/schema.sql` при старте. Если переменная окружения
отсутствует, используется `false`; тогда обязательна `database.url` из
YAML/окружения. Её получает репозиторий через `get_database_target`. Не
добавляйте ORM или драйвер конкретной внешней БД без реальной задачи.

## API, валидация и OpenAPI

Каждому публичному маршруту нужны уникальный `operation_id`, русские `summary`,
`description`, корректные status codes и примеры успешных request/response.
Входные Pydantic-поля имеют `description`, examples и обоснованные ограничения;
JSON-ввод использует `extra="forbid"`, если расширяемость не спроектирована.
Новая версия получает `api/vN/router.py` и URL-префикс `/vN`.

OpenAPI JSON не сохраняется в Git. Он строится приложением по адресу
`/vN/openapi.json`. Контрактные тесты запускают сервис, извлекают этот документ
и обходят все операции без списка конкретных маршрутов: проверяют схему,
описания, примеры, ограничения и выполнение документированных запросов.
Добавление нового endpoint не требует переписывать тест под его имя, но требует
полной документации в OpenAPI.

SSE должен использовать `StreamingResponse`, выдавать кадры по мере генерации,
проверять отключение клиента, в `finally` освобождать ресурсы и завершаться
событием `end` с закрытием соединения. Документируйте его как
`text/event-stream`, с `x-event-schema` и `x-streaming`.

## Тесты и готовность

Сначала пишите минимальный осмысленный тест, затем реализацию. Имя теста должно
показывать в `pytest -v` условие и ожидаемое поведение. Не добавляйте тесты ради
строк покрытия или проверки внутренней реализации.

Изменение готово после успешных `uv lock --check`, Ruff format/lint, mypy,
полного pytest и `uv build`. При изменении Dockerfile и доступном Docker также
соберите образ, проверьте `/v1/health/ready` и корректно остановите контейнер.
